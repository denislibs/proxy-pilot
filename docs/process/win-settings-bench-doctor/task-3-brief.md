### Task 3: Сервер настроек на loopback

**Files:**
- Create: `win/crates/app/src/websrv.rs`
- Modify: `win/crates/app/src/main.rs`

**Interfaces:**
- Produces: `Settings Server::start(shared_state) -> Result<SettingsUrl, Error>`, `SettingsUrl { url: String }`, `Server::stop()`.

**Требования безопасности — это локальный сервер, который правит настройки:**

- Привязка **строго к `127.0.0.1`** и к **порту 0** (система выдаёт свободный) — не к фиксированному, чтобы не занимать чужой и не быть предсказуемым.
- **Одноразовый токен** в URL, сгенерированный из системного источника случайности, сравнивается **в постоянное время**. Без токена — `404`, а не `403`: не подтверждаем существование сервера тому, кто не знает токена.
- **Сервер живёт только пока открыто окно настроек** и гасится по таймауту бездействия (15 минут) — постоянно открытая дверь в настройки ни к чему.
- Проверять заголовок `Origin`/`Referer` для запросов, меняющих состояние, и отвергать чужие: иначе страница в браузере пользователя сможет постучаться к нам.
- Никаких файлов с диска: страница вшита в бинарь.

**Почему это безопасно принять.** Слушатель на loopback доступен любому процессу пользователя — но такой процесс и так может прочитать `config.toml` и подменить сам бинарь. Токен защищает от случайного захода браузера по угаданному адресу, а не от локального злоумышленника с правами пользователя.

- [ ] Шаги по обычному циклу. Тесты: токен обязателен, неверный токен даёт 404, посторонний `Origin` отвергается, сервер гаснет по таймауту, порт действительно loopback.
