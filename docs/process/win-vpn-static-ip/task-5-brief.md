# Task 5 — Профиль сети: данные и решение

**Files:** `win/crates/core/src/netprofile.rs` (новый), `win/crates/core/src/config.rs`, `win/crates/core/src/lib.rs`

**Produces:**
```rust
pub struct NetProfile { pub office_ip: Option<Ipv4Addr>, pub office_mask: Option<Ipv4Addr>,
                        pub office_gateway: Option<Ipv4Addr>, pub office_dns: Vec<Ipv4Addr> }
pub struct AdapterConfig { pub dhcp: bool, pub addr: Option<Ipv4Addr>, pub set_by_us: bool }
pub enum ProfileAction { SetStatic { .. }, SetDhcp, LeaveAlone }
pub fn decide_profile(in_office: bool, profile: &NetProfile, current: &AdapterConfig) -> ProfileAction
```

## Ты владеешь правками конфига в этом плане

Добавь в `Config`:
- `office_subnets: Vec<Ipv4Net>` — офисные подсети для маршрутов туннеля. **Это не то же самое, что существующее `office_networks`**: там GUID сетей NLM для опознания «где мы», из которых маршрут не выводится. Два разных набора данных с похожими именами — дай новому полю комментарий, объясняющий разницу, иначе на нём кто-нибудь споткнётся.
- `net_profile: NetProfile` и тумблер автоматики туннеля.

Все новые поля с `#[serde(default)]`: существующие конфиги на дисках не должны перестать читаться.

## Таблица решений

```
в офисе, адрес задан, адаптер наш или на DHCP -> статический адрес и офисные DNS
не в офисе, статику ставили мы               -> DHCP
адрес не задан                               -> не трогаем сеть вообще
адрес прописан не нами                       -> не трогаем: это чужая настройка
```

**Последняя строка — главная.** Сбрасывать в DHCP статику, которую поставил не ты, значит ломать чужую конфигурацию машины, причём молча и в момент смены сети. Человек с прописанным вручную адресом для доступа к лабораторному стенду не должен обнаружить, что наш инструмент его стёр.

**«Пустой адрес значит не управляем»** — то же правило, что на macOS: инструмент не начинает распоряжаться сетью просто потому, что его установили.

## Ограничения

- Чистая логика, **без единого ввода-вывода**. `netsh` не здесь.
- `proxypilot-core` остаётся без платформенных зависимостей.
