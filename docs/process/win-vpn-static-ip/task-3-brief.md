# Task 3 — Чужой туннель

**Files:** `crates/winnet/src/tunnel_state.rs` (новый), `crates/winnet/src/lib.rs`

**Produces:**

Сигнатуры в плане раскрыты не полностью — эти считать заданием. Если по коду выйдет, что нужны другие поля, скажи об этом в отчёте и объясни.

## Критерий, ради которого задача существует

**Не «есть ли туннельный адаптер», а «лежит ли уже маршрут в наши офисные сети через чужой туннель».**

Разница принципиальная: у пользователей Tailscale или WireGuard туннельный адаптер поднят постоянно. Наивная проверка «есть tun — значит занято» не дала бы поднять офисный туннель никогда, и функция была бы мертва у всех, кто пользуется хоть каким-то VPN. Логика переносится из macOS-версии дословно — там она такая по той же причине.

Если чужой туннель в наши сети уже поднят — **не трогаем ни подъём, ни останов** и показываем это в меню (задача 7). Два туннеля разом дерутся за маршруты, и проигрывает пользователь.

## Ограничения

- Функции чистые, без ввода-вывода. Таблицу маршрутов собирает вызывающий.
- `Ipv4Net` берётся из `proxypilot-core::net` (задача 2), своя копия не заводится.

## Приёмка

- [ ] Постоянно поднятый Tailscale (маршрут `100.64.0.0/10` через tun) не считается чужим при офисных сетях `10.x`.
- [ ] Туннель с маршрутом в офисную сеть считается чужим.
- [ ] Наш собственный туннель не считается чужим.
- [ ] Маршрут в офисную сеть через **не**-туннельный адаптер (мы физически в офисе) не считается чужим туннелем.
- [ ] Пустая таблица маршрутов — `false`, не паника.
- [ ] Коммит: `feat(win): распознавание чужого туннеля по маршрутам`
