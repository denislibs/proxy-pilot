# Task 7 — Сеть и туннель в интерфейсе

**Files:** `win/crates/app/src/tray.rs`, `win/crates/app/src/settings_page.rs`, `win/crates/app/src/main.rs`

**Produces:** секции сети и туннеля в меню трея и на странице настроек.

## Состав

- Где мы (уже есть строка «Сеть: …» — **не переписывать**), какой адрес применён, состояние туннеля.
- Кнопки «поднять» / «опустить» туннель.
- Тумблер «поднимать вне офиса» (спека 8.5: по умолчанию **выключено**, туннель поднимается руками).
- Кнопка сборки профиля и кнопка установки службы — **обе с явным предупреждением про UAC до нажатия**, а не после.
- Если OpenVPN не установлен — раздел неактивен **с внятным объяснением**, а не просто серый.
- Если поднят чужой туннель в наши сети — показать это и не предлагать подъём (задача 3).
- Сказать прямо: пока туннель поднят, DNS-запросы идут в офис (спека 8.2). Это осознанная плата, и пользователь должен знать о ней до подъёма, а не догадываться.

## Ограничения

- **Дописываешь, не переписываешь.** Пункты режимов, строка демоции и строка «Сеть: …» из планов 2 и 3 остаются как есть.
- Изменения настроек идут единственным путём — через канал `Cmd`. Не заводи второй.
- Правило «смена порта моста не применяется на лету» (`apply_change`, `#[must_use]`) не ослабляется.
- Ничего в этой задаче не показывает UAC само по себе: кнопка установки службы **запускает** привилегированную операцию, и запрос показывает Windows — но никакой другой путь к UAC не появляется.
- CSP страницы не ослабляется; inline-скриптов не добавлять (в задаче 4 плана 3 это уже обошли обычной формой).
