### `docs/setup.md` — два новых раздела, ничего не удалено

Задача явно требует не задваивать README и setup.md. Два пункта из
`task-5-brief.md` — «как настроить системный прокси руками, если
автоматическое управление выключено» и «куда смотреть логи» — это
конфигурационные детали, а не то, что должно знать первое впечатление от
README; они хорошо ложатся в setup.md, который уже отвечает на вопрос «как
настроить каждую часть». В самом setup.md этих двух вещей раньше не было
вовсе (проверено — не только не было раздела, но `manage_system_proxy`,
`PROXYPILOT_LOG` и путь к логам не упоминались нигде в файле).

Добавлено:

- В таблицу «Где что лежит» — строка «Логи»
  (`%APPDATA%\ProxyPilot\logs\proxypilot.YYYY-MM-DD.log`, посуточная
  ротация) и абзац про `PROXYPILOT_LOG` — оба факта взяты из
  `crates/bridge/src/log.rs` (`LOG_FILE_PREFIX = "proxypilot"`,
  `ENV_VAR = "PROXYPILOT_LOG"`, `tracing_appender::rolling::daily`) и
  `crates/app/src/main.rs` (`log_dir = dir.join("logs")`, где `dir` —
  родитель `Config::path()`, то есть `%APPDATA%\ProxyPilot`).
- Новый раздел «Если выключили автоматическое управление прокси» — что
  значит `manage_system_proxy = false` (комментарий в
  `crates/core/src/config.rs`: групповая политика или явный `-x` у
  отдельных команд) и куда руками вписать `127.0.0.1:3129` в настройках
  Windows. Порт подтверждён как `bridge_port` (дефолт `3129`,
  `crates/core/src/config.rs`).

## Список «чего не делает» — сверка с `doctor.rs`

Источник истины — `coverage_gap_warning()` в `crates/app/src/doctor.rs`
(строки 392–404): ProxyPilot управляет только WinINET, не управляет
WinHTTP (`netsh winhttp` от администратора), Firefox (свои настройки,
WinINET не читает) и приложениями, читающими `HTTP_PROXY`/`HTTPS_PROXY` из
окружения.

И `README.md`, и уже существовавший раздел в `docs/setup.md` («Чего
программа не делает», не трогался) называют ровно эти три пункта, той же
причиной у каждого. Формулировки не скопированы дословно (в `doctor.rs`
это один абзац для лога, в README — три пункта списка + подпись
«диагностика показывает то же»), но по содержанию — та же тройка и те же
причины, ни одним пунктом ни больше, ни меньше. Тест `doctor.rs`
(`the_coverage_gap_warning_is_always_present_even_when_everything_else_is_fine`)
подтверждает, что диагностика печатает эту строку всегда, а не только при
проблеме — на этот факт README тоже прямо ссылается («тот же список
показывает диагностика»).
