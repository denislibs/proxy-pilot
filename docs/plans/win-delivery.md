**Goal:** довести до состояния, в котором коллеге можно дать ссылку.

**Architecture:** один самодостаточный `.exe` без установщика для ядра; отдельная команда ставит службу профиля тем, кому нужна статика. Подпись Authenticode в конвейере сборки. Обновления — проверка релизов и замена бинаря.

**Spec:** [`docs/superpowers/specs/2026-08-30-proxypilot-windows-rust-design.md`](../specs/2026-08-30-proxypilot-windows-rust-design.md) — раздел 12.

## Единственное, чего я не могу сделать сам

**Сертификат Authenticode — это закупка, а не задача программиста.** Нужен OV или EV на юрлицо, с проверкой организации удостоверяющим центром. Конвейер я подготовлю целиком: сборка, подпись, проверка подписи, публикация — останется вставить сертификат в секреты CI.

Почему это не косметика. Неподписанный exe, который открывает слушающий сокет и правит ключи прокси в реестре, — учебниковый профиль малвари. SmartScreen покажет предупреждение при первом запуске у каждого получателя, а эвристики антивирусов на такое реагируют охотно. Для инструмента, который раздают коллегам по ссылке, это разница между «скачал и работает» и «скачал, испугался, написал в чат».

До появления сертификата раздача возможна, но каждый получатель будет один раз проходить через предупреждение — это надо честно написать в инструкции, а не умалчивать.

## Global Constraints

Все прежние остаются в силе: loopback, однократная привязка, восстановление системного прокси на любом выходе, ядро без UAC, три проверки CI, комментарии по-русски.

### Task 1: Метаданные и версия

Версия в одном месте, из неё — `CFBundle`-аналоги Windows: `FileVersion`, `ProductVersion`, `CompanyName`, `FileDescription`, иконка приложения. Ресурсы вшиваются в exe.

Тег релиза обязан совпадать с версией в манифесте — иначе релиз уезжает с чужим номером внутри. Это уже сделано в macOS-версии проекта, повторить проверку в CI.

- [ ] Коммит: `build(win): метаданные и версия в бинаре`.

---

### Task 2: Подпись

`signtool` в конвейере, сертификат и пароль — из секретов CI, никогда из репозитория. Отметка времени обязательна: без неё подпись протухает вместе с сертификатом, и через год все раздачи начинают ругаться.

Конвейер должен собираться и **без** сертификата — тогда шаг подписи пропускается с явным предупреждением в логе, а не падает. Иначе разработка без секретов станет невозможной.

- [ ] Проверка подписи после неё же (`signtool verify /pa`) — подписать и не проверить значит узнать о проблеме от пользователя.
- [ ] Коммит: `ci(win): подпись Authenticode с отметкой времени`.

---

### Task 3: Обновления

Проверка релизов на GitHub, сравнение версий, скачивание и замена бинаря с перезапуском. Дифференциальных обновлений не делаем — это неоправданная сложность для инструмента такого размера.

**Обязательные свойства:**
- Проверка **не блокирует запуск** и не мешает работе: сеть может быть недоступна, а прокси нужен именно тогда.
- Скачанный файл **проверяется подписью** перед заменой. Обновление, которое не проверяет, что скачало, — это канал доставки чужого кода прямо в процесс, который правит системные настройки.
- Замена происходит при следующем запуске, а не под работающим процессом.
- Пользователь может выключить проверку.

- [ ] Тесты на сравнение версий (включая предрелизные и «текущая новее опубликованной»), на поведение без сети, на отказ при неверной подписи.
- [ ] Коммит: `feat(win): проверка и установка обновлений`.

### Task 4: Релизный конвейер

По тегу `win-v*`: собрать релиз, подписать, проверить подпись, приложить `proxypilot.exe` к релизу, сгенерировать заметки.

Отдельно от существующего macOS-конвейера — у них разные теги и разные артефакты; смешивать значит ломать оба сразу.

- [ ] Коммит: `ci(win): релиз по тегу`.

### Task 5: Инструкция получателю

Короткий README для Windows-части: что это, куда смотреть после запуска, что делать при предупреждении SmartScreen (пока нет сертификата), как настроить системный прокси, если пользователь выключил автоматическое управление, и куда смотреть логи.
