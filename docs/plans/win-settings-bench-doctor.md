# ProxyPilot Windows — план 3: настройки, замер, диагностика

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** довести приложение до самодостаточного: человек может настроить его без правки файлов, сравнить скорость путей, продиагностировать неполадку и поставить в автозапуск.

**Architecture:** окно настроек — не нативный тулкит, а страница, которую приложение отдаёт само на отдельном loopback-порту и открывает в браузере пользователя. Замер и диагностика живут там же и в трее. Изменения настроек идут тем же каналом команд, что и переключение режима, — единственным путём в супервизор.

**Tech Stack:** Rust 2021, tokio (уже есть), `windows` для реестра автозапуска. Никаких новых UI-зависимостей.

**Spec:** [`docs/superpowers/specs/2026-08-30-proxypilot-windows-rust-design.md`](../specs/2026-08-30-proxypilot-windows-rust-design.md) — этот план реализует разделы 11.2 (окно настроек), 6.3 в части диагностики и часть 12 (автозапуск).

**Предыдущие планы:** [план 1](2026-08-30-proxypilot-win-core-bridge.md) — ядро и мост; [план 2](2026-08-30-proxypilot-win-winnet-tray.md) — опознание сети, системный прокси, супервизор, трей. Оба завершены, 156 тестов.

## Ключевое решение: настройки в браузере, а не в нативном окне

Спека 11.2 допускала оба варианта. Выбираю браузер, и вот почему — обстоятельства с момента написания спеки изменились в его пользу:

- В приложении **уже крутится оконный цикл сообщений**, которым владеют `tray-icon` и `muda`, причём `muda` ставит на то же окно свой подкласс через `SetWindowSubclass`. Второй GUI-фреймворк (`native-windows-gui`) пришёл бы со своими предположениями о цикле событий и подклассах — это ровно тот стык, где ошибки не воспроизводятся.
- Асинхронный стек уже есть, отдать страницу — десятки строк, а не зависимость.
- `bench` и `doctor` выводят простыни текста, которым в нативной форме тесно, а в HTML — естественно.
- Ноль новых зависимостей в дереве, которое придётся подписывать.

Плата: настройки открываются в браузере, а не «внутри приложения». Для инструмента, который сам по себе является локальным прокси, это уместно.

## Global Constraints

Действуют для **всех** задач. Первые четыре унаследованы и остаются в силе.

- Слушатель моста привязывается **строго к `127.0.0.1`** и **привязывается один раз за жизнь процесса**. Смена порта требует явного перезапуска и обязана быть действием пользователя, а не тихой перепривязкой.
- **`Router::get()` имеет ровно одну не-тестовую точку вызова** (`serve.rs`, `pick_route`) и ровно одного не-тестового писателя (`supervisor.rs`).
- **Любой путь завершения процесса восстанавливает системный прокси.** `RestoreOnDrop`, флаг `BRIDGE_STOPPED`, `Exit` и оконная процедура завершения сеанса — не трогать.
- **Ничто в этом плане не требует прав администратора.** Автозапуск — `HKCU`, сервер настроек — loopback.
- **Изменения настроек идут единственным путём** — через канал `Cmd` в супервизор. Второй писатель в `Router` в обход канала был бы молча затёрт следующим пересчётом.
- Rust edition 2021, `rust-version = "1.75"`.
- CI: `cargo test --all`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --all --check`.
- Комментарии объясняют **почему**, по-русски.

### Task 1: Замер путей

**Files:**
- Create: `win/crates/bridge/src/bench.rs`
- Modify: `win/crates/bridge/src/lib.rs`

**Interfaces:**
- Consumes: `Route`, `Upstreams`, `connect_via`.
- Produces: `BenchResult { label: String, route: Route, bytes: u64, elapsed: Duration, error: Option<String> }`, `BenchResult::speed_bps(&self) -> Option<u64>`, `bench_all(&Upstreams, url: &str, limit: u64, timeout: Duration) -> Vec<BenchResult>`, `fastest(&[BenchResult]) -> Option<&BenchResult>`.

**Что меряем и что не меряем.** Один поток и короткий файл — **намеренно**. Цифры сравнивают пути между собой, а не измеряют скорость линии; абсолютную скорость меряют многопоточно и с разгоном. Если подать это как измерение канала, человек справедливо не поверит числам.

Мост в сравнении **не участвует как путь** — он проверка, а не маршрут: измерять его значит измерять один из тех же трёх путей плюс накладные расходы на лишний хоп.

- [ ] **Step 1: Написать падающий тест**

`win/crates/bridge/src/bench.rs`:

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use std::time::Duration;

    fn res(label: &str, bytes: u64, ms: u64, err: Option<&str>) -> BenchResult {
        BenchResult {
            label: label.to_string(),
            route: Route::Direct,
            bytes,
            elapsed: Duration::from_millis(ms),
            error: err.map(|e| e.to_string()),
        }
    }

    #[test]
    fn speed_is_bytes_over_seconds() {
        assert_eq!(res("x", 1_000_000, 1000, None).speed_bps(), Some(1_000_000));
        assert_eq!(res("x", 500_000, 500, None).speed_bps(), Some(1_000_000));
    }

    #[test]
    fn a_failed_measurement_has_no_speed() {
        // Иначе «0 байт за 0 секунд» превратилось бы в деление на ноль
        // или в бесконечность, и путь выглядел бы бесконечно быстрым.
        assert_eq!(res("x", 0, 0, Some("отказ")).speed_bps(), None);
        assert_eq!(res("x", 0, 100, Some("отказ")).speed_bps(), None);
    }

    #[test]
    fn a_zero_duration_does_not_divide_by_zero() {
        assert_eq!(res("x", 1000, 0, None).speed_bps(), None);
    }

    #[test]
    fn fastest_ignores_failures() {
        let rs = vec![
            res("мёртвый", 0, 0, Some("отказ")),
            res("медленный", 100_000, 1000, None),
            res("быстрый", 900_000, 1000, None),
        ];
        assert_eq!(fastest(&rs).map(|r| r.label.as_str()), Some("быстрый"));
    }

    #[test]
    fn fastest_of_nothing_is_nothing() {
        assert!(fastest(&[]).is_none());
        assert!(fastest(&[res("x", 0, 0, Some("отказ"))]).is_none());
    }

    #[tokio::test]
    async fn a_dead_upstream_yields_an_error_not_a_hang() {
        let up = Upstreams { socks: Some("127.0.0.1:1".into()), http: None };
        let started = std::time::Instant::now();
        let rs = bench_all(&up, "http://127.0.0.1:1/", 1000, Duration::from_millis(500)).await;
        assert!(started.elapsed() < Duration::from_secs(5), "замер обязан укладываться в таймаут");
        assert!(rs.iter().any(|r| r.error.is_some()), "мёртвый путь обязан быть помечен ошибкой");
    }

    #[tokio::test]
    async fn every_configured_route_is_measured_and_labelled() {
        let up = Upstreams { socks: Some("127.0.0.1:1".into()), http: Some("127.0.0.1:2".into()) };
        let rs = bench_all(&up, "http://127.0.0.1:1/", 1000, Duration::from_millis(300)).await;
        // напрямую + socks + http
        assert_eq!(rs.len(), 3, "получили: {:?}", rs.iter().map(|r| &r.label).collect::<Vec<_>>());
        assert!(rs.iter().any(|r| matches!(r.route, Route::Direct)));
        assert!(rs.iter().any(|r| matches!(r.route, Route::Socks(_))));
        assert!(rs.iter().any(|r| matches!(r.route, Route::Http(_))));
    }

    #[tokio::test]
    async fn an_unconfigured_upstream_is_not_measured() {
        let up = Upstreams { socks: None, http: None };
        let rs = bench_all(&up, "http://127.0.0.1:1/", 1000, Duration::from_millis(300)).await;
        assert_eq!(rs.len(), 1, "только «напрямую»");
    }
}
```

- [ ] **Step 3: Написать реализацию**

Требования к `bench_all`:

- Меряет каждый **настроенный** путь: всегда `Direct`, плюс `Socks`/`Http`, если заданы.
- Для каждого: набрать через `connect_via` с общим таймаутом, отправить простой `GET`, читать тело до `limit` байт или до конца, засечь время от начала набора до последнего байта.
- Любая ошибка — в поле `error`, а не паника и не пропуск строки: путь, который не отработал, надо показать как не отработавший.
- Каждый замер ограничен `timeout` целиком, а не по-фазно.
- Не использует HTTP-библиотек: запрос простой, а лишняя зависимость в дереве, которое придётся подписывать, не нужна.

`speed_bps` возвращает `None`, если была ошибка или прошло ноль времени.

`fastest` игнорирует строки с ошибкой и строки без скорости.

### Task 2: Диагностика

**Files:**
- Create: `win/crates/app/src/doctor.rs`
- Modify: `win/crates/app/src/main.rs`

**Interfaces:**
- Consumes: `Config`, `AppState`, `sysproxy::read`, `is_stale_pointer`, `list_connected`, `Prober`.
- Produces: `Check { title: String, status: CheckStatus, detail: String }`, `CheckStatus { Ok, Warn, Fail }`, `run_checks(&Config, &AppState) -> Vec<Check>`.

**Что проверяем.** Каждая проверка соответствует реальной неполадке, которую эта программа у людей вызывает:

| Проверка | Почему она есть |
|---|---|
| мост слушает свой порт | самая частая жалоба — «не работает», а слушателя нет |
| системный прокси указывает на нас | человек мог поправить настройки руками или их сбросила политика |
| в реестре наш адрес, но моста нет | прошлый процесс убили; сеть у человека не работает и он не знает почему |
| апстримы отвечают | «медленно» и «не грузится» чаще всего про это |
| текущая сеть опознана | если она не в списке офисных, `auto` уходит напрямую, и это надо видеть |
| офисных сетей ни одной | `auto` тогда всегда «не офис» — частая причина «почему прокси не включается» |
| WinHTTP, Firefox, переменные окружения | **не покрываются** нашим управлением; человек обязан это знать, иначе будет искать ошибку у нас |

Последняя строка — не проверка, а честное предупреждение. Диагностика, умалчивающая о своих границах, отправляет человека искать не там.

- [ ] **Step 2: Проверить падение.**
- [ ] **Step 3: Реализация.** `run_checks` не делает ввода-вывода сама — она получает уже собранные факты; сбор фактов живёт в вызывающем и тестируется вручную.

### Task 3: Сервер настроек на loopback

**Files:**
- Create: `win/crates/app/src/websrv.rs`
- Modify: `win/crates/app/src/main.rs`

**Interfaces:**
- Produces: `Settings Server::start(shared_state) -> Result<SettingsUrl, Error>`, `SettingsUrl { url: String }`, `Server::stop()`.

**Требования безопасности — это локальный сервер, который правит настройки:**

- Привязка **строго к `127.0.0.1`** и к **порту 0** (система выдаёт свободный) — не к фиксированному, чтобы не занимать чужой и не быть предсказуемым.
- **Одноразовый токен** в URL, сгенерированный из системного источника случайности, сравнивается **в постоянное время**. Без токена — `404`, а не `403`: не подтверждаем существование сервера тому, кто не знает токена.
- **Сервер живёт только пока открыто окно настроек** и гасится по таймауту бездействия (15 минут) — постоянно открытая дверь в настройки ни к чему.
- Проверять заголовок `Origin`/`Referer` для запросов, меняющих состояние, и отвергать чужие: иначе страница в браузере пользователя сможет постучаться к нам.
- Никаких файлов с диска: страница вшита в бинарь.

**Почему это безопасно принять.** Слушатель на loopback доступен любому процессу пользователя — но такой процесс и так может прочитать `config.toml` и подменить сам бинарь. Токен защищает от случайного захода браузера по угаданному адресу, а не от локального злоумышленника с правами пользователя.

- [ ] Шаги по обычному циклу. Тесты: токен обязателен, неверный токен даёт 404, посторонний `Origin` отвергается, сервер гаснет по таймауту, порт действительно loopback.

### Task 4: Страница настроек

**Files:**
- Create: `win/crates/app/src/settings_page.rs` (HTML в константе)
- Modify: `win/crates/app/src/websrv.rs`

**Что на странице:** апстримы SOCKS5 и HTTP с индикаторами доступности, порт моста, список офисных сетей с кнопкой «эта сеть — офис» рядом с текущей, bypass-список, тумблер управления системным прокси, тумблер автозапуска, кнопки «Замерить» и «Диагностика» с выводом там же.

**Правила, которые страница обязана соблюдать:**

- **Смена порта моста не применяется на лету.** Поле сохраняется, но рядом появляется явное «перезапустите ProxyPilot, чтобы порт вступил в силу». Тихая перепривязка убила бы свойство, ради которого продукт переписан, — об этом прямо сказано в докблоке супервизора.
- Всё остальное применяется немедленно, через тот же канал `Cmd`.
- Валидация — та же `Config::validate`, а не вторая копия правил в JavaScript. Страница показывает ошибку, которую вернул сервер.
- Кнопка «эта сеть — офис» подставляет **GUID текущей сети** и её имя — человек не должен переписывать GUID руками.

- [ ] Шаги по обычному циклу; ручная проверка обязательна: открыть страницу, сменить апстрим, убедиться что режим применился без перезапуска; сменить порт и убедиться, что появилось предупреждение и порт **не** перепривязался.

### Task 6: Автозапуск

**Files:**
- Create: `win/crates/winnet/src/autostart.rs`
- Modify: `win/crates/winnet/src/lib.rs`

**Interfaces:** `is_enabled() -> Result<bool, WinNetError>`, `enable(exe: &Path) -> Result<(), WinNetError>`, `disable() -> Result<(), WinNetError>`.

Ключ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `ProxyPilot`. **`HKCU`, а не `HKLM`** — второе требует администратора, а весь план обязан обходиться без него.

Путь пишется в кавычках: без них путь с пробелами (`C:\Program Files\…`) Windows разберёт неверно. `is_enabled` сверяет не только наличие значения, но и то, что оно указывает на **этот** экземпляр: иначе перенос exe оставит запись, ведущую в никуда, а тумблер будет показывать «включено».

- [ ] Шаги по обычному циклу; ручная проверка: включить, увидеть запись в реестре, выключить, убедиться что удалена.
