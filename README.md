# ProxyPilot для Windows

Мост между приложениями и корпоративным прокси. Держит **один постоянный
адрес — `127.0.0.1:3129`**, а за ним переключает верхнее звено: SOCKS5,
HTTP-прокси или прямое соединение. Клиенты (git, npm, браузер) настраиваются
на этот адрес один раз и больше про это не вспоминают.

Опознаёт офисную сеть и сам решает, нужен ли прокси: в офисе — через
апстрим, дома — напрямую. Переключение происходит само, без вмешательства.

## Главное свойство

**Смена маршрута не рвёт уже установленные соединения.** Открытый туннель
или скачивание доигрывает на том пути, по которому начался; новый маршрут
получают только новые соединения. Из-за этого не нужны ни повторные
подключения клиентов, ни защита от «дребезга» сети — переключение просто
безопасно само по себе.

## Что уже есть

- мост: HTTP-CONNECT, обычный HTTP, коннекторы SOCKS5 / HTTP / прямой,
  проверка живости апстримов, список исключений;
- опознание сети через Network List Manager (по GUID сети, а не по угадыванию
  шлюза — поднятый VPN такой признак не подделывает);
- управление системными настройками прокси Windows с восстановлением на любом
  пути завершения процесса, включая аварийный;
- иконка в трее, страница настроек в браузере, замер скорости, диагностика,
  автозапуск;
- split-tunnel через установленный OpenVPN GUI — доступ к внутренним
  ресурсам без заворачивания всего трафика в офис;
- служба статического IP для тех, кому доступы выданы под фиксированный
  адрес;
- проверка обновлений по релизам GitHub, версия и метаданные в самом `.exe`.

## Как получить и запустить

Установка не нужна — `proxypilot.exe` самодостаточен, двойной клик.

Собранные бинари публикуются на странице
[Releases](https://github.com/denislibs/proxy-pilot/releases) при выходе
тега `v*` — конвейер (`.github/workflows/release.yml`) собирает
`proxypilot.exe` и `proxypilot-bridge.exe`, по возможности подписывает и
прикладывает к релизу.

**Релиза пока нет.** Пока это так, единственный способ получить бинарь —
собрать из исходников:

```
cargo build --release -p proxypilot-app
```

Готовый `target/release/proxypilot.exe` — тот же самодостаточный файл, что
попал бы в релиз. Отдельно собирается `proxypilot-bridge.exe` — тот же мост
без интерфейса, для консоли.

Минимальная версия Rust — **1.88** (её требует транзитивная зависимость
`time`).

После запуска появится иконка в трее — оттуда всё: настройки, диагностика,
замер скорости, выход. Дальше — [`docs/setup.md`](docs/setup.md):
апстрим, опознание офиса, настройка клиентов, туннель, статический адрес и
разбор частых случаев «не работает».

## Предупреждение SmartScreen — оно будет, и вот почему

Программа не подписана сертификатом Authenticode. Сертификат — это закупка
(нужен OV или EV на юрлицо с проверкой организации удостоверяющим центром),
и его пока не купили. Конвейер публикации к подписи уже готов — он подпишет
`.exe`, как только в секретах CI появятся сертификат и пароль, — но
подписывать пока нечем.

**Значит, при первом запуске каждый получатель увидит предупреждение Windows
SmartScreen.** Это ожидаемо, а не баг: `.exe` открывает слушающий сокет и
правит ключи прокси в реестре — по формальным признакам ровно то поведение,
от которого SmartScreen защищает.

**Что делать:** в окне предупреждения нажать «Подробнее», затем «Выполнить в
любом случае». Один раз на машину — повторных запусков это не касается.

**Когда появится сертификат**, эту инструкцию менять не придётся: релизный
конвейер уже устроен так, что при наличии секретов `WINDOWS_CERTIFICATE_BASE64`
и `WINDOWS_CERTIFICATE_PASSWORD` подписывает `.exe` автоматически и с
отметкой времени. Предупреждение исчезнет для новых релизов; уже скачанные
неподписанные `.exe` задним числом не подписываются.

## Чего продукт НЕ делает

Он управляет только системными настройками WinINET — теми, что видны в
«Панели управления» → «Свойства обозревателя». Мимо него идут:

- **WinHTTP** — свои настройки; используют службы и часть приложений,
  правится только `netsh winhttp` от администратора;
- **Firefox** — собственные настройки прокси, WinINET не читает;
- приложения, которые сами берут адрес из переменных окружения
  `HTTP_PROXY` / `HTTPS_PROXY`.

Тот же список показывает встроенная диагностика (меню трея → Диагностика).
Если что-то из перечисленного ведёт себя не так, как ожидалось, — дело не в
ProxyPilot, проверяйте настройки именно того приложения, которое не слушается.

## Права администратора

Ядро не показывает UAC ни разу. Единственный запрос прав во всём продукте —
установка службы статического IP, и она необязательна: кому статика не
нужна, тот не увидит ни одного диалога.

## Устройство

| Крейт | Ответственность |
|---|---|
| `proxypilot-core` | чистая логика: решение о маршруте, конфиг, список исключений. Без зависимостей от платформы |
| `proxypilot-bridge` | сам мост: слушатель, коннекторы, атомарная смена маршрута, супервизор |
| `proxypilot-winnet` | всё, что говорит с Windows: NLM, реестр прокси, события сети, автозапуск |
| `proxypilot-app` | трей, страница настроек, диагностика, замер, проверка обновлений |
| `proxypilot-netsvc` | служба статического IP — единственное место с UAC |

Подробное обоснование каждого решения, включая то, почему мост свой, а не
готовый gost, — в [`docs/design.md`](docs/design.md). Ход работы, включая
разборы и ревью, — в [`docs/process/`](docs/process/).
