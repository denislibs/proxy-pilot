# ProxyPilot для Windows

Мост между приложениями и корпоративным прокси. Держит **один постоянный
адрес — `127.0.0.1:3129`**, а за ним переключает верхнее звено: SOCKS5,
HTTP-прокси или прямое соединение. Клиенты настраиваются один раз и больше
про это не вспоминают.

Опознаёт офисную сеть и сам решает, нужен ли прокси: в офисе — через
апстрим, дома — напрямую.

## Главное свойство

**Смена маршрута не рвёт уже установленные соединения.** Открытый туннель
доигрывает на том пути, по которому начался; новый маршрут получают только
новые соединения. Из-за этого не нужны ни повторные подключения клиентов,
ни защита от «дребезга» сети — переключение просто безопасно само по себе.

## Состояние

Работа не закончена. Что уже есть:

- ядро и мост: HTTP-CONNECT, обычный HTTP, коннекторы SOCKS5 / HTTP / прямой,
  проверка живости апстримов, список исключений;
- опознание сети через Network List Manager (по GUID сети, а не по угадыванию
  шлюза — поднятый VPN такой признак не подделывает);
- управление системными настройками прокси Windows с восстановлением на любом
  пути завершения процесса, включая аварийный;
- иконка в трее, страница настроек в браузере, замер скорости, диагностика,
  автозапуск.

Чего ещё нет: split-tunnel через установленный OpenVPN GUI, служба
статического IP, подпись Authenticode, обновления. Планы на всё это лежат
в [`docs/plans/`](docs/plans/).

**CI по этому коду ещё ни разу не исполнялся** — всё проверялось локально
(282 теста). Первый прогон на `windows-latest` покажет то, чего локальный
прогон показать не мог.

**Подписи пока нет.** SmartScreen покажет предупреждение при первом запуске
у каждого получателя. Это ожидаемо для неподписанного `.exe`, который
открывает слушающий сокет и правит ключи прокси в реестре, — то есть по
формальным признакам выглядит ровно как то, от чего SmartScreen и защищает.

## Как настроить

Пошаговая инструкция — [`docs/setup.md`](docs/setup.md): первый запуск,
апстрим, опознание офиса, настройка клиентов, туннель, статический адрес и
разбор частых случаев «не работает».

## Сборка

```
cargo build --release -p proxypilot-app
```

Готовый `target/release/proxypilot.exe` самодостаточен, установщик не нужен.
Отдельно есть `proxypilot-bridge.exe` — тот же мост без интерфейса, для
консоли.

Минимальная версия Rust — **1.88** (её требует транзитивная зависимость
`time`; проверяется отдельной работой в CI).

## Права администратора

Ядро не показывает UAC ни разу. Единственный запрос прав во всём продукте —
установка службы статического IP, и она необязательна: кому статика не
нужна, тот не увидит ни одного диалога.

## Чего продукт НЕ делает

Он управляет настройками WinINET — теми, что видны в «Свойствах
обозревателя». Мимо него идут:

- **WinHTTP** — свои настройки, меняются `netsh winhttp` от администратора;
- **Firefox** — собственные настройки прокси, WinINET не читает;
- приложения, берущие `HTTP_PROXY` / `HTTPS_PROXY` из окружения.

Тот же список показывает встроенная диагностика. Если что-то из
перечисленного ведёт себя не так, причина не в этой программе.

## Устройство

| Крейт | Ответственность |
|---|---|
| `proxypilot-core` | чистая логика: решение о маршруте, конфиг, список исключений. Без зависимостей от платформы |
| `proxypilot-bridge` | сам мост: слушатель, коннекторы, атомарная смена маршрута, супервизор |
| `proxypilot-winnet` | всё, что говорит с Windows: NLM, реестр прокси, события сети, автозапуск |
| `proxypilot-app` | трей, страница настроек, диагностика, замер |

Подробное обоснование каждого решения — в [`docs/design.md`](docs/design.md).
Ход работы, включая разборы и ревью, — в [`docs/process/`](docs/process/).

## Происхождение

устройство, свой мост, свои решения — они и их причины перечислены
в [`docs/design.md`](docs/design.md).
